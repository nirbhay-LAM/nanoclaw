# Release: Container Watchdog

**Date:** 2026-03-22
**Commit:** eeb7ff2, 88286b3
**Container rebuild:** No (host-side only)
**Service restart:** Yes

## What Changed

### Container Watchdog

Added a watchdog timer that detects and recovers from stuck containers automatically. Previously, if a container became unresponsive, messages would silently queue up and RSK would stop responding until a manual service restart.

**How it works:**
- Watchdog starts when messages are sent to a container (new spawn or piped to active)
- Resets on any agent output activity
- If no activity within 5 minutes, the watchdog kills the stuck container and re-queues messages
- Messages are re-fetched from the database and processed by a fresh container
- No manual intervention needed

**Diagnostics:** When triggered, logs: `Watchdog: container unresponsive, killing and re-queuing` with container name and idle duration.

**Configuration:** `WATCHDOG_TIMEOUT` env var (default: 300000ms / 5 minutes)

### sendMessage Logging

`sendMessage()` in the group queue now logs when it can't find an eligible active container, making it easier to diagnose delivery failures.
